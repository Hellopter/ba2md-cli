# 3.x.2.5 Database Design · Conditional

Read this constraint when tables, entities, collections, indexes, migrations, or persistence behavior change. When not applicable, omit the body or write N/A as the active template permits.

## Research and Writing

- Verify current physical names, fields, types, keys, constraints, and indexes.
- Identify readers, writers, data ownership, and lifecycle.
- Describe the target schema and data changes.
- Cover transactions, locks and concurrency, migration, backfill, dual write, and rollback.
- Explain API-model-to-persistence-model mappings at load-bearing points.

## Output Format

```markdown
#### 3.x.2.5 Database Design

| Entity / table | Current fields, indexes, constraints | Target change | Readers / writers | Transaction and concurrency | Migration / backfill / rollback | Change type | Evidence / Claim ID |
|----------------|--------------------------------------|---------------|-------------------|-----------------------------|---------------------------------|-------------|---------------------|
| | | | | | | | |
```

## Quality Gate

- Physical identifiers come from production schemas or migrations.
- Do not invent tables or fields and do not cite Java test sources.
- Migration and rollback are executable or explicitly marked GAP/PROPOSAL.
