# 3.x.2.4 External Interface Design · Conditional

Resolve this section in the Template Coverage Plan before deep research. Read this constraint when the system exposes or consumes HTTP, gRPC, webhooks, files, or another protocol boundary.

## Research and Inventory

- Search all relevant routing, protocol, contract, client, and provider locations; do not stop at the first matching endpoint.
- Record every discovered external interface in the Implementation Inventory as in scope or excluded with a reason.
- Verify each complete composed route or protocol identifier.
- State caller, provider responsibility, and source IDs.
- Compare each current request/response with precise target field changes.
- Cover errors, authentication, authorization, compatibility, idempotency, rate limits, timeouts, and retry responsibility.

## Quality Gate

- Every in-scope external interface from the inventory appears in the table; the section is not a representative sample.
- Derive full paths from actual route composition, never from names or wiki prose.
- Derive precise fields from production contracts, never Java test sources.
- Every omitted discovered interface has an explicit exclusion reason.
- Compatibility strategy and failure responsibility are explicit.
