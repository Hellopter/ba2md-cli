# 消费 wiki（地图）

Wiki 是地图（SUMMARY）：身份、归属、边界、术语。精确当前标识进 draft 时再从 `sources/<id>` 锚。

本文件是节点 2 的单源：怎么走树、读哪些页、何时停、要不要派子代理。确认范围见 SKILL 节点 3。完成条件见 SKILL 节点 2。

## 树

跑 `ba2md discover --json`。每个 `wiki/<id>/` 的结构真相是 `outline.tree`（嵌套的目录 + 页）。树上没有的路径不打开。对着这棵树走，不把 logical-project `marker` 当阅读顺序。

根是具体的 `wiki/<id>/…`。坏路径与孤儿记下来。

## 读哪些页

对着树走，不按文件名合同。

```text
打开：
  1. 每棵挂载树的根层页（depth 最浅的 md，无论叫什么）
  2. 根层页链出的、且树里存在的邻页
  3. 子树：仅当需求用语或已读页点名了该目录名 / 标题 / 仓名
用法：
  - 几乎全是链接的页 → 当目录，跟着树里有的链接走
  - 浅层长文 → 通读（地图正文）
  - 其余 → 点到才打开
停：能列出候选 sources/<id>
```

`index.md` 若在根层，按根层页打开；是目录还是长文，打开后看内容。

## 候选仓

三处相交：wiki 正文里的仓名、`discover` 的 `sources/`、intake 点名。

对上 `sources/<id>`：路径或正文相等，其次去掉 `-wiki` / `_wiki`，再查 discover 清单。不在本节点扫源码 README。

每条候选一行理由（owns / 在路径上 / 被提及）。wiki 未覆盖但需求仍指向某仓：记 GAP，该仓仍可进候选。

## 谁读

一份 `wiki/<id>/`：主会话读完（下一跳要问用户）。

两份及以上：每个 wiki 一个子代理，只交回已读路径 + 候选表 + GAP。子代理不写 `research-plan.md` / `progress.yaml`。主会话合并后写盘。

## 写入 research-plan

列出**实际打开过的路径**和带依据的候选。空表不算完成。词表有则记。
